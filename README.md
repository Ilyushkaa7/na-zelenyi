# На зеленый - марафон ПДД

Статический сайт на HTML, CSS и JavaScript. Работает на GitHub Pages без
серверной части, SQLite, регистрации и npm-зависимостей.

## Локальный просмотр

```powershell
python -m http.server 8000 --bind 127.0.0.1 --directory public
```

Открыть http://127.0.0.1:8000/. Также можно запустить `start.ps1`.
Python здесь только раздаёт готовые файлы для просмотра. На GitHub Pages он не нужен.
Открывать `index.html` через `file://` нельзя: браузер должен загрузить модули и JSON по HTTP.

Первые 20 авторских пояснений доступны по адресу `/#explanations`:
вопросы первого билета, картинки, все варианты, правильный ответ и авторский разбор.
Просмотр не меняет прогресс. Текстовая копия находится в `AUTHOR_EXPLANATIONS.md`.

## Публикация на GitHub Pages

1. Загрузить проект в репозиторий GitHub, в ветку `main`.
2. В репозитории открыть Settings - Pages и выбрать Source: GitHub Actions.
3. В Actions вручную запустить Publish GitHub Pages: он проверяет данные и механику,
   затем публикует только папку `public`. Исходные PDF и старые локальные базы не публикуются.

Workflow: `.github/workflows/pages.yml`. Сайт использует относительные пути,
поэтому работает как в корне домена, так и по адресу `https://USER.github.io/REPO/`.
Сборка не нужна. Публикация запускается только вручную; push выполняет отдельные проверки
Check site и не размещает сайт. GitHub Pages пока не включён.
Локальные исходные PDF не входят в Git; их можно повторно скачать инструментом импорта.

## Сохранение

- Имя необязательно, код не нужен. Один профиль на браузер и адрес сайта.
- Прогресс находится в `localStorage`: текущая карточка и порядок ответов,
  результат ответа, очередь повторов, текущая сессия, итоги и статистика по дням.
- Каждый ответ записывается до показа результата. При отказе хранилища ответ
  не принимается; интерфейс сообщает об ошибке и позволяет повторить попытку.
- Предыдущая запись хранится резервной копией с проверкой целостности.
  При повреждении основной записи восстанавливается предыдущая, с уведомлением.
  Повреждённые данные без пригодной копии не перезаписываются автоматически.
- Web Locks сериализуют изменения между вкладками; номер версии записи дополнительно
  не позволяет устаревшей вкладке затереть более новое сохранение.
- В настройках можно изменить имя или сбросить данные после подтверждения.
  Сброс удаляет только два ключа этого марафона, остальные данные домена не затрагиваются.
- Очистка данных браузера удалит прогресс. В приватном режиме сохранение зависит
  от политики браузера и обычно исчезает после закрытия приватных окон.
  Между браузерами, устройствами и адресами сохранения не переносятся.
  В частности, localhost, 127.0.0.1 и GitHub Pages имеют разные хранилища.
- После 30 дней ничего не удаляется: аккаунтов и системы друзей больше нет.

Папка `var` со старой SQLite, если она осталась от прежней локальной версии,
сохранена как архив и игнорируется. Новый сайт её не читает и не публикует.

## Механика

- 800 официальных вопросов A, B, M, 541 иллюстрация.
- Вопросы идут случайными пятёрками исходных билетов. Уже закрытые не возвращаются,
  поэтому частично пройденная пятёрка может быть короче пяти карточек.
- Варианты перемешиваются на каждом новом показе. Сохранённая незаконченная карточка
  восстанавливается с тем же порядком. Правильный ответ проверяется по ID.
- Первый правильный ответ закрывает вопрос. Ошибка возвращает его после случайных
  5-10 других ответов. Верный повтор назначает контроль после случайных 50-75.
  Верный контроль закрывает вопрос, любая повторная ошибка запускает короткий цикл.
- Повтор остаётся в своей тематической пятёрке и получает приоритет при наступлении
  срока. Одновременно подошедшие повторы обслуживаются по сроку.
- В конце, когда свежих вопросов нет, оставшиеся повторы появляются раньше.
- После каждого ответа есть пояснение. «Дальше» нажимает сам пользователь.
- «Закончить занятие» сохраняет статистику сессии и дня и показывает итоги.
  Продолжение возвращает к сохранённой карточке. Уже принятый ответ не считается дважды.
  Дни считаются по московскому времени.

## Редактирование текстов

- `public/content/ui.json` - основные тексты интерфейса.
- `public/content/questions.json` - официальные вопросы, ответы, ID и ссылки на картинки.
- `public/content/explanations.json` - единственный файл для редактирования пояснений.
  У каждой записи явно указаны `ticket` (билет) и `question` (вопрос), затем идут
  `original` (оригинальное пояснение МВД) и `my` (твой разбор).
  В каждом разделе есть `text` и `rule`. Ранее написанные 20 пояснений первого билета
  сохранены в `my`; остальные 780 личных полей пустые.
- Меняй `my.text`, а при необходимости `my.rule`. Пока `my.text` пустой,
  сайт показывает `original.text` с подписью «официальный комментарий МВД».
  Как только заполнишь `my.text`, сайт использует твой текст. Если `my.rule` пустой,
  ссылка на правило берётся из `original.rule`. Другие файлы менять не нужно.
  Повторный импорт обновляет `original`, сохраняя `my`. Страница с 20 пояснениями
  всегда показывает первый билет.
- `content/transcription-overrides.json` - сверенная ручная транскрипция
  растрового PDF билета 4, вопросы 6-10.
- `sources/manifest.json` - ссылки на 200 исходных PDF.
- `sources/commentary.json` - оригинальные комментарии и верные ответы для сверки.
- `public/images/` - иллюстрации с сохранёнными обозначениями и водяными знаками МВД.
  Извлекаются из PDF в WebP без дополнительного сжатия с потерями.
  На странице ограничены шириной 520 px и шириной контейнера, без увеличения
  сверх исходного размера. Водяной знак вписан в исходные пиксели, отдельного слоя нет.

После редактирования обновить страницу. Правки текста сохраняют прогресс.
Изменение состава вопросов или ключей требует отдельного переноса сохранений
и новой `revision`, чтобы не применять старый результат к изменённому вопросу.

Материалы получены с официальной страницы 9 октября 2026 года. Это дата получения,
а не подтверждение даты редакции каждого билета. Исходные PDF сохранены для сверки.
Структура всех карточек проверена, выборочные страницы сверены визуально;
полная редакторская сверка всех 800 ещё не завершена.

## Проверки и повторный импорт

```powershell
node tools/check-content.mjs
node --test tests/*.test.mjs
node --check public/app.mjs
```

Для проверок нужен Node.js 22+. Тесты проверяют полный проход, интервалы повторов,
повторные ошибки, восстановление карточки, отказ записи, резервную копию, конфликт
вкладок, сброс только собственных ключей и московские границы дня.

Для импорта PDF нужны Python, `pdfplumber`, `pypdf`, `Pillow`, `pypdfium2`:

```powershell
python tools/download_official.py
python tools/import_official.py
```

Эти инструменты нужны для подготовки материалов; сам сайт обходится без них.
